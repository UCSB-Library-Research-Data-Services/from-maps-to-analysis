Working with Data

Learning Objectives

This lesson focuses on learning more about the different types of geographic data and learning how to import and work with your own data in ArcGIS Online. At the end of this workshop you will:

  • Have a better understanding of various vector and raster geospatial data types
  • Know how to import external tabular data into ArcGIS Online
  • Know how to edit or add data to a feature layer
  • Better understand the difference between continuous and categorical raster layers
  • Know how to export data from ArcGIS Online to your local machine

Review: Annotations vs. Data

In Workshop 1, we started with sketch layers to draw points, lines, and polygons directly on top of the map. While sketches are convenient for quick markups and annotations, they are not true GIS data layers. Sketches lack an underlying database table and cannot be queried, filtered, or used in spatial analysis.

In contrast, feature layers link geometries (points, lines, or polygons) to structured records in an attribute table. Each feature has defined attributes, or fields (e.g., name, speed limit, road type, elevation) with specific data types (such as text strings, numbers, and dates). This tabular structure makes it possible to filter features, symbolize data based on its attributes, and calculate spatial relationships.

Raster vs Vector Data

Geographic data generally falls into two primary models: vector and raster.

Vector Data

So far we have only looked at vector data. Vector data represents discrete geographic features using coordinate geometry:

  • Points: Single \((X, Y)\) coordinate pairs representing discrete locations (e.g., bike racks, bus stops, accident locations).
  • Lines (Polylines): Ordered sequences of vertices connecting locations to represent linear features or networks (e.g., bike paths, roads, transit routes, streams).
  • Polygons: Closed shapes enclosing an area defined by connected coordinate vertices (e.g., campus buildings, land parcels, parks, water bodies).

Every shape is tied to a row in an attribute table, where each column holds specific properties describing that feature. For example, if we pop open the table and look at the attributes for the “Library” building,

First selecting the polygon Library

Then opening the Attribute Table under layer options by clicking the ...

Each polygon in the table has many fields and values associated with it. Building names, floor counts, area, who edited the file, and when it was last updated, among other fields a user may find helpful when analyzing their data.

Attributes may be divided into three types:

  • Nominal: information with labels and names - building type

  • Numerical: information that can be counted or has numerical importance - shape area

  • Ordinal: information that can be ordered or ranked in some way - floor count

Raster Data

Raster data represents the landscape as a regular grid of square cells (pixels) organized into rows and columns.

  • Single-band rasters: Each pixel contains a single numerical value representing a continuous measurement (such as elevation in a Digital Elevation Model [DEM], slope, or temperature) or an integer code representing a category (such as land cover types).
  • Multi-band rasters: Each pixel contains multiple values across different spectral channels or bands (such as red, green, blue, and near-infrared bands in aerial photography or satellite imagery).

Below is a single band raster. The value of each pixel is elevation.

Below is an 8-band raster with band #7 (near IR) as red, band #3 (green) as green, and band #1 (coastal blue) as blue. This type of image displays are often called “false-color” because they do not respect the RGB channel alignment. This can help to highlight some features, such as vegetation that has a strong signal in near infrared (NIR) wavelengths

Categorical Raster - Land Cover

Categorical vs. Continuous Data

Continuous data are best represented by numbers, and are logically consistent when you do so. Smaller numbers = less of some measurement.

On the other hand, categorical data can be text or numeric. The value of any numbers used do not necessarily reflect any mathematical value, but it may. For example, while the values below have a natural order (The 3 Little Piggies Construction Scale), the numbers are ordinal but arbitrary:

  • 1 = reinforced concrete or steel beam
  • 2 = wood stick construction
  • 3 = baked brick masonry
  • 4 = adobe
  • 5 = sun brick / mud daub
  • 6 = straw bail

While elevation is a continuous raster (values change smoothly along a numerical gradient representing a quantity), other rasters are categorical rasters (e.g., land cover classification datasets from the Living Atlas, where integer cell values represent categories such as urban development, forest, or water).

Multi-band Rasters

So far we have worked with single-channel, or 1-band rasters. However, perhaps we are more familiar with 3-channel images, because our eyes see best in the red-green-blue color space. For geospatial data, think of this as satellite or aerial views.

For digital images, 3 ‘bands’ of wavelengths are stored separately. When the computer combines them together, we humans see something akin to what we see when we look at nature with our eyes. However, we can swap in other bandwidths of radiation, such as near infrared, or microwave, and see completely other things.

NoteCRS

A note on Coordinate Reference Systems

In ArcGIS Online, the default projection and Coordinate Reference System (CRS) is WGS 1984 Web Mercator Auxiliary Sphere, also used by the Global Positioning System (GPS).

Coordinate systems can be divided into two main categories: Projected and Geographic Coordinate Systems.

  • Projected Coordinate Systems use a 2D flat surface to define locations and is measured in linear units. Locations are identified by x,y coordinates

  • Geographic Coordinate Systems use a 3D spherical surface measured in angular units to define locations on earth. A point is referred by its latitude and longitude.

There are plethora of CRSs that all have different accuracy and other advantages depending on your location and extent of your area of interest. Here is a good website to look at the different CRSs: https://epsg.io/

Editing Feature Layers

Now that we have imported data into ArcGIS, we might also want to modify this data. For vector data, we can modify attributes and values stored in the underlying table or the feature itself by editing locations and shapes, or adding and removing specific features. For raster data, those transformations are generally done using some form of calculation on the entire raster, or specific values targeted via conditions, rather than by manually editing pixel values. We will talk more about raster calculations in our third workshop. For today, we will focus on editing vector data (or feature layers in ArcGIS jargon) in this workshop.

WarningThis goes beyond the map

It is important to understand that when we are editing a feature layer, it is independent of the map. You are actually changing the data stored under your content.

This also means that you might not have the right to edit some of the data you are using in your map because you do not own them! A potential workaround is to create a local copy of the data, but some data provider do not allow this either.

Exporting Data

At some point in your analysis, you might want to also download the data in addition to your map, for example, to move to a scripted environment such as R and Python to conduct statistical analysis. This is a multi-step process: first, you will have to export the feature layer in a downloadable format; then you will be able to download this layer to your local computer.

You can not export a layer from the Map Viewer, you will need to first return to the “My Content” view. You can do this by using the “Burger” menu at the top-left of your Map view and selecting Content.

  • Once in the My content view, locate and click on the spatial trailhead layer you imported from the CSV file to go to the Overview page of that layer.

  • Unfold the menu on the right completely, select Export data, and choose the GeoJSON format.

  • On the next window, leave the default options and choose your ucsb_bike folder as location. Click on Export. Note that exporting data can take some time, so be patient :)

  • Once the export is completed, you should automatically be redirected to the Overview page of this new dataset. This time, Download should be available in the menu on the right side of the page. Click on it and select a location on your local computer and a filename.

Creating Shaded Relief (Hillshade) on the Fly

One use for a DEM is to make a shaded relief layer. That is a classic view that gives the terrain realistic three-dimensional depth and surface texture, we can generate a shaded relief visualization dynamically:

  1. Duplicate the ucsb_local_dem layer.
  2. Rename the two DEM layers for clarity: name the top layer Elevation (Color) and the bottom layer Elevation (Shaded Relief).
  3. Change the symbology style to Shaded Relief.

Shaded relief simulates how sunlight illuminates terrain, casting shadows based on the position of the sun measured as two angles: Azimuth and Altitude

  • Azimuth: The compass direction from which the illumination source (the sun) originates, measured in degrees clockwise from north (0° = North, 90° = East, 180° = South, 270° = West). In cartography, the sun is traditionally positioned in the northwest (315°) or west (270°) to match how the human brain interprets light and shadow, preventing an optical illusion known as “relief inversion” where mountains appear as valleys. For our map, we position the light source from the west.
  • Altitude: The angle of the sun above the horizon, measured from 0° (level with the horizon at sunrise/sunset) to 90° (directly overhead at solar noon). A lower altitude (e.g., 30°–45°, typical of low winter sun) produces longer, more dramatic shadows that accentuate ridge lines, canyons, and valleys.

We can adjust those angles to show the sun in the morning or evening here in Santa Barbara.

Adjust the transparency of the top colored elevation layer so the shaded relief beneath shows through, creating an illuminated 3D terrain effect under our roads.

Analysis Workflow Overview

  1. Slope Calculation: Use raster analysis tools to calculate a slope raster from the DEM, expressing terrain steepness in degrees or percent rise.
  2. Zonal Statistics as Table: With the slope raster and the road network loaded, run Raster Analysis > Zonal Statistics as Table to compute summary statistics (such as the maximum or mean slope) for each road line.

  1. Joining Statistics to Roads: The zonal statistics tool outputs a standalone data table. To visualize these slope measurements on the map, join the table back to the road vector layer using Tools > Summarize data > Join Features, matching on a common identifier such as OBJECTID.

  1. Once joined, roads can be symbolized by slope steepness, allowing us to pinpoint the steepest hill climbs for our ride!
